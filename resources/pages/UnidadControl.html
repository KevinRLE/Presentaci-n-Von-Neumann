Unidad de Control (UC)

Arquitectura Von Neumann & Gestión de Memoria

En el modelo de Von Neumann, la Unidad de Control (UC) es considerada el verdadero cerebro de la PC. Mientras la ALU realiza las operaciones matemáticas y lógicas, la UC coordina, ordena y sincroniza la ejecución de instrucciones, administrando el ciclo de vida de los procesos y comunicándose directamente con la unidad de manejo de memoria (MMU).

🖥️ Del Código Fuente a la Ejecución en RAM

Antes de que la UC pueda ejecutar una aplicación, el compilador transforma el código mediante análisis Morfosintáctico y Semántico hasta generar el código objeto (binario). Posteriormente, el Montador (Linker) enlaza las bibliotecas del sistema (p. ej. DLL) y el Cargador (Loader) transfiere la imagen del proceso a la memoria RAM.

🔄 Ciclo de Instrucción, Timer y TRAPs

La UC nunca se detiene. Para garantizar que ningún proceso monopolice la CPU, el sistema utiliza un Timer Clock con intervalos de tiempo llamados Time Slices.

⚠️ Interrupciones & TRAP: Cuando expira el Time Slice o se requiere una entrada/salida (E/S), el timer envía una interrupción al procesador. El comando TRAP se utiliza para alternar estados y permitir el cambio de contexto entre el modo usuario y el modo núcleo.

📍 Registros de la CPU supervisados por la UC

PC / UPC Program Counter

Guarda la dirección de memoria de la siguiente instrucción a ejecutar. Determina la app o proceso en turno durante su Quantum.

RI Registro de Instrucción

Guarda el código binario de la instrucción que se está ejecutando en tiempo real (ej. copiar, pegar, operaciones de cálculo).

SP Stack Pointer

Puntero especial que guarda la ubicación del elemento superior dentro de la pila (Stack) de la memoria asignada al proceso.

Status Registro de Estado

Define el nivel de privilegio de ejecución del microprocesador: User Mode (usuario con permisos restringidos) o Kernel Mode (administrador con acceso total al hardware).

RIED Registro de Identificación

Identifica el proceso activo en el procesador y apunta a su respectiva Tabla de Páginas para la traducción de memoria virtual.

⚙️ Gestión de Procesos, BCP y Core Image

📦 Proceso y Core Image

Un proceso requiere 4 elementos clave en RAM: Código Objeto, Estructuras de Datos, Variables/Constantes y Datos. El Core Image es la foto completa del estado del proceso en ejecución.

🗂️ BCP (Bloque de Control de Proceso)

Estructura de datos que salva el estado completo del proceso (Registros, Instrucciones y Mapa de Memoria). Permite restaurar el proceso exacto donde fue pausado.

⏱️ Quantum & Planificación

Tiempo asignado por el planificador (Scheduler) bajo algoritmos como Round Robin para forzar la alternancia justa entre tareas.

🌀 Pseudoparalelismo

La alternancia ultrarrápida entre procesos fragmentados por quantums simula la ejecución simultánea en un único núcleo físicamente.

🧭 Traducción Virtual: UC $\rightarrow$ MMU $\rightarrow$ RAM / Disco

Para evitar accesos directos desordenados a la RAM, la UC envía una Dirección Virtual aleatoria a la MMU (Memory Management Unit). La MMU se encarga de traducirla e interpretarla hacia una dirección física real.

⚠️ Manejo de Fallos (Page Fault & SWAP):
Si la dirección solicitada no está en la memoria RAM o no hay marcos disponibles, se produce un error de acceso. La MMU notifica el fallo y solicita una nueva dirección a la UC. Si la RAM está saturada, el sistema invoca el proceso de Swap (Intercambio), creando una estructura auxiliar en el Disco Duro (Memoria Virtual):
  • Windows: Gestiona la memoria virtual mediante un archivo de intercambio dinámico.
  • Linux: Asigna la memoria virtual mediante una partición dedicada del disco (Partición Swap).
